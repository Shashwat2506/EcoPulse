SYSTEM ARCHITECTURE & METHODOLOGY

EcoPulse: Smart Sustainability Tracker

An end-to-end, production-grade carbon footprint analytics platform and CI/CD demonstration project built with Flask, Docker, Jenkins, and Kubernetes.

1. PROJECT PURPOSE & SCOPE

EcoPulse is an intuitive personal carbon accounting system designed to eliminate ambiguous greenhouse gas estimates. By capturing user activity data across four primary categories—Transportation, Home Energy, Waste, and Lifestyle—EcoPulse computes annualized mass balances in kilograms of CO2-equivalent (kg CO2e) and converts them into standardized metric tonnes.

Single Source of Truth: All dashboard charts, category breakdown percentages, and historical logs are dynamically derived from atomic activity records stored in persistent SQLite storage.

3. CI/CD & DEVOPS ARCHITECTURE

EcoPulse is engineered for university Cloud Computing & DevOps evaluation (CCA 2). It satisfies multi-tier containerization and orchestrated deployment workflows:

01

Source Control

Git feature branches with automated commit tracking on GitHub.

02

Automated Tests

Jenkins triggers pytest executing unit tests for calculation modules, endpoints, and input sanitization.

03

Dockerization

Multi-stage or slim Python build, non-root user execution, packaged with production WSGI Gunicorn.

04

Registry Push

Images tagged with semantic build numbers and pushed securely to Docker Hub registry.

05

Kubernetes on Minikube

Declarative deployment with rolling update strategy, container resource limits, and /healthz liveness/readiness probes.

4. APPLICATION HEALTH & ENDPOINTS

The system provides both user-facing visual interfaces and machine-readable REST endpoints for automated infrastructure monitoring:

  • GET / - Interactive carbon tracking dashboard and 3D Earth view.
  • GET /healthz - Liveness/Readiness probe returning HTTP 200 with database health status.
  • GET /api/entries - List all stored user assessment entries.
  • POST /api/entries - Create and persist a new assessment log.
  • PUT /api/entries/<id> - Recalculate and update an existing log.
  • DELETE /api/entries/<id> - Delete an assessment log.
  • GET /api/history - Chronological dataset for historical trend visualization.
